# 大團系統 系統架構

> 狀態：第一版。需求來源為 [PRD](PRD.md)。目前先在本機開發，部署相關決策列在第 7 章。

## 1. 前提

- 開發方式：由產品負責人搭配 AI 開發，沒有現成團隊。
- 架構原則：優先降低維運負擔，只有在壓力測試顯示需要時才增加元件。

## 2. 整體架構

採用模組化單體，不拆微服務。名額、費用與報名必須在同一筆交易中一起成功或失敗。

```text
員工手機 / 旅行社、窗口、平台後台
              │
    CDN + WAF（*.平台網域）
       │                │
  前端應用          API 服務（可水平擴充）
                   │  由網址判定旅行社
       ┌───────────┼──────────┐
  PostgreSQL     物件儲存    工作佇列
  （主要資料）   （圖片、條款、 │
                  匯出檔）   背景工作程序
                              ├─ 寄信
                              ├─ Excel 匯入與匯出
                              ├─ 釋出逾時名額
                              └─ 到期刪除個資
```

## 3. 技術選型

| 項目 | 選擇 |
|---|---|
| 語言 | TypeScript，前後端共用型別與驗證規則 |
| 前端 | Next.js |
| 後端 | NestJS |
| 資料庫 | PostgreSQL |
| 工作佇列 | 以 PostgreSQL 實作（例如 pg-boss），量變大時再換成 SQS |
| 封裝 | 所有程式以容器封裝 |

暫不使用 Redis 與獨立搜尋服務；壓力測試顯示資料庫撐不住時，再增加排隊機制或快取。

## 4. 關鍵設計

| 需求 | 做法 | 取捨 |
|---|---|---|
| 不超賣 | 由 PostgreSQL 交易直接扣名額，條件不符就失敗；同時保留多種名額時固定鎖定順序，避免死結 | 熱門梯次會排隊，需用壓力測試驗證 |
| 15 分鐘保留 | 保留紀錄寫入資料庫並設到期時間；查詢時排除已逾時的保留，背景工作再定期清理 | 清理延遲不會多佔名額 |
| 即時剩餘名額 | 前端每 5～10 秒輪詢，搭配極短快取 | 顯示有幾秒延遲，實際判斷以保留當下為準 |
| 租戶隔離 | 共用資料庫，每張表都有旅行社 ID，並以 PostgreSQL 列級安全（RLS）作為第二道防線 | 成本低、好維運；單一旅行社要獨立資料庫時需另外處理 |
| 子網域 | 萬用字元憑證與網域，由網址判定旅行社 | 開通新旅行社不需動基礎設施 |
| 員工帳號 | 帳號為員工編號，每個活動各一組；密碼以 scrypt 雜湊儲存 | 雜湊刻意消耗運算資源，尖峰同時登入須納入壓力測試 |
| 設定密碼連結 | 只存雜湊，連結只在產生當下回傳一次，14 天內有效且只能使用一次 | 窗口之後無法再次匯出同一個連結，需要時重新產生，舊連結立即失效 |
| 登入狀態 | 隨機值放在 HttpOnly Cookie，資料庫只存雜湊，12 小時後過期；Cookie 路徑限定單一活動 | 各旅行社子網域屬於同一個網站，SameSite 擋不住彼此的請求，因此另外檢查 Origin |
| 暴力破解 | 連續失敗 5 次鎖定 15 分鐘，帳號不存在、密碼錯誤與鎖定中回傳相同結果 | 員工編號容易猜到，有心人可以讓特定員工暫時無法登入；上線前應加上依來源 IP 限流 |
| 旅行社後台 | 與前台同一個網址判定旅行社，路徑為 `/admin`，登入 Cookie 路徑限定 `/api/v1/agency`；同樣的鎖定規則 | 活動代碼不能使用 `admin` |
| 活動頁開關 | 手動或依時間自動擇一，每次請求即時計算，關閉時已登入的員工也不能存取 | 不需要排程工作，也不會有開關延遲 |
| 敏感欄位 | 應用層加密，金鑰由金鑰管理服務保管；查看與匯出都寫入稽核紀錄 | 加密欄位無法直接搜尋，需靠員工編號等欄位查找 |
| 大量工作 | 寄信與 Excel 匯入匯出放進佇列，提供進度與失敗狀態 | 需處理重試與避免重複寄送 |
| 報名尖峰 | 依已排定的開放報名時間提前擴充 | 需要排程功能，但比臨時自動擴充可靠 |

## 5. 流量估算

設計目標沿用 PRD：單一活動 5,000 人、尖峰 1,000 人同時上線。推估保留名額的尖峰約為每秒幾十到一兩百筆，此為推估值，須以壓力測試驗證。

## 6. 本機開發環境

所有服務（前端、API、資料庫與周邊服務）都在 Docker Compose 內執行，以 `docker compose up --build` 一鍵啟動，電腦上只需要 Docker。原始碼掛載進容器，修改後自動重新載入。

| 正式環境 | 本機替代 | 用途 |
|---|---|---|
| RDS PostgreSQL | PostgreSQL 容器 | 主要資料，RLS 與名額交易 |
| S3 | 待定，開發上傳功能時加入 | 圖片、條款、匯出檔 |
| SES | Mailpit | 攔截所有信件，不寄給真實收件人 |
| KMS | 本機開發金鑰 | 敏感欄位加密，僅限開發使用 |
| 子網域 | `abc-travel.lvh.me` | 指回本機，用於測試多旅行社 |

## 7. 部署前待決

- [ ] 本機 S3 相容服務：MinIO 官方映像檔已不再提供，開發上傳功能時從 SeaweedFS 等替代方案選定
- [ ] 運算平台：建議 ECS 容器；替代方案為 Lambda
- [ ] 區域：建議 AWS 台北區域（ap-east-2）；須以 AWS 官方清單確認 Fargate、SES 等服務，並請法務確認個資儲存位置與跨境傳輸
- [ ] 平台網域：正式環境建議使用專屬網域，並設定 SPF、DKIM、DMARC
