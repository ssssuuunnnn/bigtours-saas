# 大團系統 PRD

> 狀態：第一版。本文件記錄已確認的結論，上線前仍需確認的項目列在第 14 章。

## 1. 產品概述

團體行程報名 SaaS。平台服務多間旅行社；旅行社在後台建立報名網頁相關設定（含活動、自選行程與自訂旅客資料欄位），提供給企業員工使用。企業員工可在前台瀏覽行程資訊、選擇報名人數、填寫旅客資料並完成報名。

## 2. 角色與權限

### 2.1 後台角色

| 角色 | 身分 | 職責 |
|---|---|---|
| 平台人員 | 平台經營者 | 經營平台，開通平台權限給旅行社 |
| 旅行社人員 | 旅行社的平台操作人員 | 建立基本報名資料與報名網頁相關設定，報名網頁提供給企業員工使用 |
| 企業窗口 | 企業方窗口 | 設定可操作報名網頁的企業員工資料，權限見 2.4 |

帳號與角色：

- 平台人員為每間旅行社開第一個管理員帳號，再由旅行社管理員新增其他人員。
- 旅行社人員分為管理員與操作員；只有管理員可以管理帳號、查看完整個資及匯出個資。
- 企業窗口帳號由旅行社人員建立。
- 旅行社人員與企業窗口都可以寄送員工帳號信、產生設定密碼連結。

### 2.2 租戶模型

- 平台的客戶是旅行社，平台會服務多間旅行社。
- 每間旅行社是獨立租戶，彼此的資料與權限完全分開、沒有關聯。

### 2.3 前台角色

| 角色 | 職責 |
|---|---|
| 企業員工 | 瀏覽行程、選擇報名人數、填寫旅客資料、完成報名 |

### 2.4 企業窗口權限

存取範圍僅限自家企業。

| 功能 | 權限 |
|---|---|
| 員工名單 | 可新增、修改、匯入 |
| 員工帳號開通 | 可寄送帳號信、產生設定密碼連結 |
| 報名進度 | 可查看誰已報名、誰未報名 |
| 報名明細與費用 | 可查看員工自付與補助金額 |
| 身分證、護照等個資 | 不可查看 |
| 活動、行程、價格、分房 | 不可修改 |

### 2.5 資料層級

```text
平台
└─ 旅行社（獨立租戶）
   └─ 企業客戶
      └─ 活動（對應一個報名網頁，有自己的設定）
         ├─ 梯次（日期、名額）
         ├─ 自選行程、旅客類型與價格、旅客欄位
         └─ 員工名單（補助金額、眷屬上限）
            └─ 報名（一位員工一筆）
               └─ 旅客（員工本人與眷屬）
```

- 一個活動只屬於一家企業。多家企業參加同一行程時，由旅行社複製活動後各自設定，名額也分開計算。
- 企業窗口帳號屬於企業，一位窗口可管理該企業的所有活動。
- 員工名單屬於活動，每次活動可設定不同補助金額；提供從上一個活動複製名單的功能。

### 2.6 報名網頁網址與品牌

- 網址格式：`旅行社代號.平台網域/活動代碼`。
- 每間旅行社可設定自己的 Logo 與主色，每個活動可另外設定主視覺圖片。
- 每個活動設定報名開始與結束時間。
- 活動頁開關：旅行社可選擇手動開啟或關閉活動頁，或設定開始與結束時間由系統自動開關，兩種方式擇一；需要臨時關閉時，切回手動再關閉。
- 活動頁開關與報名期間分開設定：活動頁開關決定員工能否進入網站，報名期間決定員工能否報名。
- 活動頁關閉時，所有員工都不能登入，包含已報名的員工；頁面只顯示尚未開放或已關閉。
- 活動頁關閉時，保留中的名額不能送出，到期後釋出；設定密碼連結仍可使用，但要等活動頁開啟才能登入。
- 旅行社手動關閉活動頁前，後台顯示確認提示與目前保留中的人數。
- 設定結束時間時，後台提醒應排在分房公布與出發之後，員工才能查看分房結果。

## 3. 員工報名資格

- 企業窗口維護員工名單，只有名單內的員工可以報名。
- 員工以帳號（員工編號）與密碼登入報名網站。不使用簡訊驗證，以避免簡訊成本。
- 報名對象為員工本人與眷屬，由員工填寫同行者資料；眷屬人數上限可依員工設定，留空時套用活動預設上限。
- 員工本人預設必須參加；旅行社可依活動開放「只有眷屬參加」，此時員工是報名人但不是旅客，補助仍可折抵眷屬費用。

### 3.1 帳號開通與登入

- 寄送帳號信：旅行社人員或企業窗口從後台觸發，系統寄送帳號信給員工，信中附設定密碼連結。
- 另外提供連結：旅行社人員或企業窗口可產生設定密碼連結，另外提供給沒有信箱或收不到信的員工。
- 連結產生紀錄：產生設定密碼連結時，記錄產生人與時間，並寄 Email 通知員工；沒有信箱的員工只留紀錄。
- 設定密碼：員工開啟連結後輸入兩次密碼確認；完成後顯示帳號（員工編號）與報名網站連結，點連結前往登入頁。
- 密碼規則：至少 8 個字元，需同時包含英文與數字。
- 連結效期：設定密碼連結 14 天內有效且只能使用一次；重新寄送或產生後，舊連結立即失效。逾期或已使用時，由旅行社人員或企業窗口重新寄送或產生。
- 連結難以猜測：使用隨機產生的長網址，不包含員工編號等可推算的資訊。
- 忘記密碼：不提供員工自助重設；由旅行社人員或企業窗口重寄帳號信，員工透過連結重新設定密碼。
- 帳號不共用：帳號屬於活動名單，同一位員工參加不同活動時，各有一組帳號與密碼。
- 登入頁：顯示活動的報名開始與結束時間。
- 報名開始前：活動頁開啟時，員工可登入查看活動資料與報名紀錄，但不能報名。
- 一人一份報名：每個帳號只對應一位員工，同一位員工不會產生重複報名。
- 個資遮罩：再次登入時，身分證、護照等已填資料只顯示部分內容。
- 報名截止後：員工仍可登入查看，但不能修改。

### 3.2 員工名單

- 匯入：支援下載 Excel 範本後批次上傳，也可在後台逐筆新增或修改；上傳時先顯示錯誤與重複資料，確認後才寫入。
- 補助金額與眷屬人數上限由企業窗口隨名單匯入。
- 報名開始後修改補助金額需記錄修改人與時間；已送出的報名不自動重算，由旅行社手動處理。
- 活動所需的其他欄位由旅行社依活動自訂。

| 欄位 | 必填 | 用途 |
|---|---|---|
| 員工編號 | 是 | 唯一識別員工，避免重複 |
| 姓名 | 是 | 顯示與核對 |
| Email | 否 | 寄送帳號信；沒有信箱時由旅行社人員或窗口產生設定密碼連結 |
| 部門 | 否 | 統計報表與篩選 |
| 補助金額 | 否 | 留空時套用活動預設金額 |
| 眷屬人數上限 | 否 | 留空時套用活動預設上限 |

### 3.3 旅客資料欄位

- 固定必填欄位：只有姓名。每位旅客都要填，旅行社不能移除或改為選填。
- 自訂欄位：旅行社可依活動在後台新增欄位，設定名稱、型態、是否必填與顯示順序。
- 欄位型態：文字、數字、日期、單選、多選。單選與多選由旅行社設定選項。
- 活動已有報名後，欄位不能刪除，也不能改型態或敏感設定；名稱、必填、選項與順序仍可調整，已送出的報名不受影響。
- 前台依設定的順序顯示，固定必填欄位排在最前面。

## 4. 付款

- 目前不做線上付款。
- 系統依報名人數與自選行程計算費用。
- 旅行社在後台手動標記付款狀態：未付、已付、已退款。付款狀態只追蹤員工自付部分；自付金額為 $0 時自動顯示「無需付款」。
- 旅行社可匯出報表，列出每位員工的整筆費用、補助與自付金額，用來向企業請款。系統先不追蹤企業是否已付款。
- 旅行社可在活動中設定付款說明，顯示於報名成功頁、員工的報名內容頁與報名成功 Email。

## 5. 名額控管

- 一個活動可以有多個梯次，每個梯次設總名額。
- 梯次總名額不能低於已報名人數；已有報名或保留中的梯次不能刪除。
- 旅行社在後台設定梯次名稱（例如快樂東京 5 日遊）、去程日期、回程抵達日期、出發時間、回程到達時間，以及去回程航班（選填，例如 CX001）。航班跨日時，回程日期填抵達當天。
- 員工選梯次時，每個梯次顯示上述資訊。沒有設定航班的梯次不顯示航班。
- 自選行程可另設名額，依梯次分開計算，不跨梯次共用。
- 眷屬也佔名額。
- 同時有多人爭取最後名額時，系統必須確保不超賣。
- 填寫頁顯示即時剩餘名額。
- 頁面區分「已額滿」與「名額保留中，可稍後再試」。
- MVP 額滿時顯示額滿並停止報名；候補放到後續版本。

### 5.1 名額保留

- 員工選好梯次、人數與自選行程後，按下「開始填寫」時保留名額 15 分鐘，以避免填完資料才發現額滿。
- 報名流程順序：選梯次、人數與自選行程，再填寫旅客資料。
- 梯次名額與自選行程名額一起保留。
- 畫面顯示倒數計時。
- 中途關閉網頁後，15 分鐘內可重新登入並繼續填寫。
- 倒數結束時自動釋出名額，已填資料先保留；員工可重新保留，若已額滿則提示無法繼續。
- 不提供手動延長。
- 填寫途中可修改人數：增加時先確認還有名額，減少時立即釋出多餘名額，兩者都不重新計時。
- 員工修改已送出的報名時，同樣保留名額 15 分鐘並顯示倒數。
- 修改送出前，原報名維持有效且名額不變；倒數結束只讓這次修改失效。
- 修改時減少人數或選項、改梯次，都在送出後才釋出原名額。

## 6. 自選行程與費用

### 6.1 自選行程

- 以選項群組設定。旅行社可為每個群組設定是否必選、可選幾項。
- 每個選項可設定價格與名額。
- 每位旅客各自選擇；填寫時提供「套用到所有旅客」。
- 選項的金額與名額依實際選擇的人數計算。

### 6.2 團費

- 旅行社可自訂旅客類型與對應團費，例如員工本人、成人眷屬、兒童眷屬、嬰兒眷屬。
- 每位旅客費用 = 團費 + 自選行程；整筆報名費用 = 所有旅客費用總和。

### 6.3 企業補助

- 補助額度與眷屬人數上限是兩條可同時設定的規則。
- 補助金額與眷屬人數上限都依員工設定，留空時套用活動預設值。
- 補助可折抵團費與自選行程，含眷屬費用。
- 員工自付 = 整筆費用 - 企業補助，最低為 $0。
- 補助用不完時不找零、不累積。
- 系統需記錄整筆費用與員工自付金額。

### 6.5 價格快照

- 報名時保存當下的團費、選項價格與補助金額。
- 活動發布後修改價格，只套用於之後的新報名；已送出的報名由旅行社手動調整。

### 6.4 住宿

- 房型與單人房差等費用，以選項群組處理。
- 系統需記錄誰與誰同房。
- 員工在報名時自行填寫同房，將同一筆報名的旅客分配到各房間。
- 支援跨員工同房：員工可填寫希望同房的同事姓名，此為意願，不會自動成立；系統不提供員工名單搜尋。
- 旅行社在後台確認最終分房並匯出，同時檢查人數是否符合房型。
- 員工選擇的房型與同房安排不符時，例如選了單人房差卻與他人同房，前台只提醒、不阻擋，最終由旅行社確認。
- 旅行社公布分房結果前，員工在前台只看得到自己填寫的內容。

## 7. 報名後異動

- 報名截止前，員工可自行修改旅客資料、同房意願、人數與自選行程。
- 增加人數或選項時須先有名額，費用重新計算；員工已付款時，差額由旅行社處理。
- 報名截止後員工不能修改，須聯繫旅行社，由旅行社在後台修改。
- 取消報名：員工提出申請，旅行社確認後才生效，名額於確認時釋出。
- 系統不自動計算退費，由旅行社依合約手動標記。
- 取消後可登入重新報名：建立新的一筆報名，舊報名保留為已取消；一位員工同時間只能有一筆有效報名。
- 保留每次修改的人員、時間與前後內容。

## 8. 成行後作業與資料匯出

- MVP 不做分車功能，由旅行社匯出後在 Excel 上作業。
- 提供保險名單匯出，匯出欄位由旅行社設定。
- 共用一個匯出功能：旅行社可選欄位並儲存成範本，例如旅客總表、分房表與保險名單。
- 匯出含個資的檔案時留下記錄。

## 9. 個資

- 沒有固定必收的敏感欄位，由旅行社依活動開啟；身分證、護照等欄位標示為敏感資料。
- 敏感欄位加密儲存，後台預設遮罩；查看完整內容與匯出都須有權限並留下記錄。
- 員工送出報名前必須勾選同意條款，條款內容由旅行社上傳。
- 眷屬資料由員工代填，條款中應說明員工須取得眷屬同意。
- 保存期限預設為活動結束後 180 天，旅行社可自行設定；到期自動刪除或去識別化。

## 10. Email 通知

| 時機 | 收件人 | 內容 |
|---|---|---|
| 旅行社人員或企業窗口觸發寄送 | 員工 | 帳號信與設定密碼連結 |
| 旅行社人員或企業窗口產生設定密碼連結 | 有信箱的員工 | 通知已有人產生連結，信中不含連結 |
| 報名成功、修改報名 | 員工 | 報名內容、費用與付款說明 |
| 取消申請的結果 | 員工 | 取消是否已生效 |
| 截止前提醒 | 尚未報名的員工 | 截止日與報名網站連結 |
| 分房結果公布 | 員工 | 最終分房 |
| 有新的取消申請 | 旅行社 | 待處理項目 |

- Email 內容不放身分證、護照等敏感資料。
- 範本由系統提供，旅行社可調整主旨、內文與寄件者名稱。
- 後台顯示寄送狀態；旅行社人員或窗口可針對失敗名單修正信箱後重寄，或改為產生設定密碼連結另外提供。

## 11. 非功能需求

- 裝置：前台採手機優先設計，後台以桌機為主。
- 流量：暫定設計目標為單一活動 5,000 人、尖峰 1,000 人同時上線（暫定值，非實際數據）。
- 驗收：上線前做一次壓力測試，以「不超賣」作為驗收標準。
- 可用性：每月 99.9%；活動開放報名期間應有監控與告警，維護時間避開已排定的開放報名時段。
- 語言：MVP 只支援繁體中文，前台文字從一開始就與程式碼分離。

## 12. 目標與範圍

### 12.1 成功指標

目標值為暫定，首批旅行社上線後再校正。

| 指標 | 暫定目標 |
|---|---|
| 旅行社從建立到發布一個活動所需時間 | 2 小時內 |
| 收到帳號信或設定密碼連結的員工中，完成報名的比例 | 80% 以上 |
| 開始填寫後，完成送出的比例 | 85% 以上 |
| 超賣件數 | 0 |

### 12.2 MVP 範圍

後台設定活動、名單與員工帳號開通、報名與名額保留、費用與補助、同房意願與分房確認、資料匯出、Email 通知與個資保護，詳見本文件各章節。

### 12.3 MVP 明確不做

- 線上付款與自動退費計算
- 候補名單
- 分車功能
- SSO 登入與簡訊通知
- 多語系介面
- 多家企業共用名額池
- 追蹤企業是否已付款

## 13. 平台收費

### 13.1 計費方式

- 依活動與報名人數計費：旅行社購買活動數量與人數，依人數量級適用不同收費級距。
- 一場活動基本費 $500；低於 200 人只收基本費；200 至 1,000 人加 $500；超過 1,000 人後，每 500 人為一單位，每單位再加 $500。
- 單一活動人數上限為 5,000 人。

### 13.2 人數計算與超量處理

- 人數以實際報名旅客數計算，含眷屬；名額保留中的旅客也計入。
- 旅行社建立活動時先選一個級距；梯次總名額不得超過所購級距。
- 使用達 80% 時提醒旅行社；達到上限時暫停新的報名，並提示旅行社升級級距、補差額，升級完成後即可繼續報名。

### 13.3 額度開通

- MVP 不做線上訂閱與自動扣款：與旅行社簽約、人工開通，後台記錄方案、合約期間與用量。
- 平台人員依合約或收款結果，在平台後台手動為旅行社開通各級距的活動數量。
- 旅行社建立活動時扣一場額度；活動尚未開放報名就刪除時，額度退回。
